\section*{Purpose and interpretation}
This supplement provides feature-schema provenance, strict output-only sensitivity, condition-level dependence analyses, selection sensitivity, failure prevalence, and operational results supporting the main manuscript. The broad estimand averages five repeated splits within each of the 24 model--dataset conditions, while the strict output-only sensitivity covers the eight Gemma-2/Llama-3.1 conditions whose archived lower-dimensional columns contain no layer-marked feature. Crossed model/dataset uncertainty, leave-one-cluster-out analyses, alternate validation objectives, and equal-budget selection are reported before diagnostic probe-envelope results. For risk metrics, lower values are better. Failure-detection AUPRC is prevalence-sensitive and should be read together with failure counts.

\section{Feature-schema provenance and strict output-only sensitivity}
The archived validator labels its lower-dimensional family \texttt{confidence\_}\allowbreak\texttt{option}. A pre-submission audit showed that this label maps to two different schemas: strict output-only columns for Gemma-2/Llama-3.1 and output columns plus three scalar layer-maximum summaries for Falcon3/Mistral/OLMo/Qwen. The broad 24-condition results are therefore interpreted as compact-summary results, and the eight-condition Gemma/Llama block is reported separately as the strict output-only sensitivity. This distinction is interpretive; the released CSV labels are preserved to maintain an exact link to the archived code and outputs.

\section{Reproducibility details}
The locked evaluator uses seeds $\{0,1,2,3,4\}$, a 60/20/20 stratified split by correctness, PCA dimensions $\{16,32,64\}$, logistic $C\in\{0.1,1,10\}$, the liblinear solver, balanced class weights, and a maximum of 1000 iterations. Standardization and PCA are fitted only on the training partition. A two-dimensional hidden array is used directly; if an archived hidden array is three dimensional, the evaluator selects the final stored layer. Candidate configuration is selected on validation data and evaluated once on its corresponding held-out split.

For the public auxiliary extractor, the prompt requests exactly one category from a labeled candidate list and instructs the model to return only the answer letter. The model chat template is applied when available. Candidate answer letters are scored with mean token log likelihood, maximum sequence length 768, and option batch size four. Extraction defaults to NF4 4-bit model weights with double quantization and FP16 computation. The hidden vector is the final non-padding prompt token from the final transformer layer. AG News uses the test CSV, TREC uses the standard training source with documented fallback, DBPedia uses the test split, and balanced sampling uses random state 42. Exact checkpoint identifiers, dataset configurations, example identifiers, prompts, file manifests, and environment specifications accompany the artifact.

The feature-schema audit is generated directly from the archived \texttt{cheap\_cols} field. A condition is classified as strict output-only only when that field contains no column name matching \texttt{layer}, \texttt{hidden}, \texttt{activation}, or \texttt{embedding}. The audit identifies eight strict conditions and sixteen compact internal-summary conditions. A whitelist patch for a future all-six-model output-only rerun is included with the analysis artifact but is not substituted for the archived results.

Risk@80\% ranks held-out examples by predicted correctness and evaluates the highest-ranked 80\%; it is not a numerical threshold transferred from validation. The two-way bootstrap independently resamples the six model labels and four dataset labels with replacement for 50,000 replicates after seed averaging. Because only four datasets are available, the manuscript also reports leave-one-dataset-out and leave-one-model-out ranges and avoids equivalence claims.
